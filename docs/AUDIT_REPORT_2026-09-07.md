# StudyAgent 微信小程序双门禁审计报告

- 审计日期：2026-09-07
- 审计基线：`main@932f00136f39bffc7f779d42f9732468e0350bc9`
- 修复分支：`audit/wechat-release-gates-20260907`
- 范围：原生微信小程序、FastAPI API、异步 Worker、存储/向量/LLM Provider、Docker、CI、微信发布配置

## 1. 结论

### 门禁 A：功能与质量门禁 —— 当前不通过

当前 GitHub Actions 基础 CI 为绿色，后端 12 个 pytest 测试通过，Vue 预览端可以构建。但现有测试不足以证明原生微信小程序和生产依赖真实可用，且源码中存在多项 P0/P1 功能缺口与生产链路错误。

### 门禁 B：微信小程序上架门禁 —— 当前不通过

仓库当前仍使用 HTTP/IP API 地址、`devMode=true`、`urlCheck=false`，隐私声明为空；此外真实 HTTPS 域名、微信合法域名、真实生产依赖、备案/隐私/AI 合规材料、体验版与真机审核均需要平台侧完成。

本分支新增 `scripts/check_wechat_release.py`，用于持续执行代码侧发布预检。该脚本通过不代表微信审核必然通过，平台侧事项仍必须人工/自动化实测。

## 2. 已确认问题清单

### P0：生产阻断/核心功能失真

#### F-001 生产 RAG 没有真正走向量检索

**现象**：文档开发模式会写入向量存储，但聊天接口实际从 SQL `DocumentChunk` 全量读取后做关键词包含匹配，没有调用 Qdrant 搜索。

**影响**：知识库规模扩大后召回质量和性能明显下降；仓库“向量检索/RAG”能力与真实实现不一致。

**修复要求**：
1. Embedding query；
2. Qdrant 按 `user_id + knowledge_base_id` filter 做 TopK；
3. 必须有相似度阈值、最大上下文长度、引用映射；
4. 资料不足必须拒答；
5. 增加召回/越权/无资料测试。

#### F-002 生产 Worker 与 API 的对象存储配置不一致

**现象**：API 容器强制 `STORAGE_PROVIDER=s3`，原 Worker 未强制 S3，按示例环境可能退回本地存储。

**影响**：API 上传对象到 MinIO/S3 后，Worker 可能在本地目录读取不到同一文件，生产解析失败。

**状态**：本审计分支已对 Docker Compose 做低风险修复，让 Worker 与 API 使用相同存储/向量 Provider。

#### F-003 生产 Worker 不生成 Embedding/不写 Qdrant

**现象**：Worker 只解析文件、切片并写 SQL，未调用 Embedding Provider，也未 upsert Qdrant。

**影响**：即使配置 Qdrant，正式上传的文件也没有可检索向量。

**修复要求**：把“解析→切片→Embedding→向量写入→READY”做成同一条幂等任务链；失败必须进入 FAILED 并记录原因，不得永久停在 PARSING。

#### F-004 Provider 在生产配置错误时会静默降级为 Fake/Local

**现象**：LLM、Vector、Storage Provider 缺配置或初始化异常时会自动退回 Fake/Local。

**影响**：生产环境可能表面可用，实际用的是假模型、假向量或容器本地文件，属于危险的 fail-open。

**修复要求**：仅 DEV_MODE 允许 Fake/Local；生产必须 fail-fast，并让 `/ready` 返回依赖失败。

#### F-005 自动测验不是基于知识库生成

**现象**：后端题目大量硬编码为 TCP 三次握手/学习闭环，与所选知识库实际资料无关。

**影响**：核心卖点“根据个人资料自动出题”未实现。

**修复要求**：题目生成必须读取知识库检索上下文，由结构化模型输出题型、选项、答案、解析、证据；加入 JSON schema 校验和内容安全处理。

#### F-006 学习计划不是 AI 计划且前端参数被硬编码

**现象**：原生小程序固定生成“14 天学习冲刺”、30 分钟/天、每周 5 天；后端只保存参数，激活后固定创建 4 个通用任务。

**影响**：不满足产品基线中“目标日期、每日学习时间、Agent 生成计划、自动调整”。

**修复要求**：增加目标、日期、时间、学习天数输入；先生成 DRAFT，用户确认后 ACTIVE；任务按日期生成；测验结果/完成度触发后续计划调整。

#### F-007 `/tasks/today` 实际返回全部历史任务

**现象**：StudyTask 没有任务日期字段，接口按 `user_id` 返回全部任务。

**影响**：今天任务、今日学习时长、首页进度会随历史累积失真。

**修复要求**：增加 `scheduled_date`/时区规则；按用户本地日期过滤；历史任务另设查询接口。

#### F-008 数据看板关键指标硬编码

`weekly_accuracy=0`，`weak_points` 固定 TCP，学习时长按完成任务数 ×15 估算。

**影响**：学习分析不可信。

**修复要求**：从 QuizAnswer、Task、Mastery 聚合真实指标，明确统计窗口与时区。

#### F-009 生产登录存在启动竞态

**现象**：`App.onLaunch` 的 `wx.login` 为异步；页面 `onShow` 可在 Token 写入前发起受保护请求。原 request 层在 `devMode=false` 时不会等待登录完成。

**状态**：本审计分支已增加共享 `authPromise/ensureAuth`，受保护请求在无 Token 时等待登录，并对 401 做一次刷新重试。

#### F-010 首页“最近知识库”点任意项都打开第一项

**原因**：列表点击没有传递当前知识库，`openChat()` 固定取 `libraries[0]`。

**状态**：本审计分支已修复。

#### F-011 0 任务时首页伪造为 4 项任务

**现象**：UI 使用 `dashboard.task_total || 4`。

**状态**：本审计分支已修复为真实 0。

### P1：明显 Bug、功能缺口或高风险质量问题

#### F-012 学习计划重复激活会重复创建任务

`activate_plan` 没有幂等保护。重复请求会再创建一组 4 个任务。

**修复**：ACTIVE 状态再次激活应幂等返回或 409；数据库侧增加业务约束/幂等键。

#### F-013 测验允许只提交部分题目，未答题不会进入错题

后端只遍历客户端传入的答案。未提交题目既没有 QuizAnswer，也没有 WrongQuestion/Mastery 影响。

**修复**：服务端必须校验完整题集或明确将未答题记为错误；测试不能再把“只交第一题”当正常成功路径。

#### F-014 简答题没有 AI 评分，原生端也没有简答输入 UI

后端只做字符串精确比较；原生小程序生成题型时也排除了 SHORT。

**修复**：加入简答输入、评分 Rubric、LLM 结构化评分、证据与人工可解释结果。

#### F-015 提交测验后不展示逐题答案和解析

后端可以 reveal，但原生结果页只显示总分/正确率。

#### F-016 对话历史能力后端有接口，原生端没有入口

进入聊天页始终创建新会话；没有历史列表、恢复会话、删除会话。

#### F-017 聊天只显示第一条 citation

其余引用、文档名/页码未展示，降低可追溯性。

#### F-018 WebSocket 不是真正流式且原生端未使用

后端一次发送完整答案为一个 token 事件；原生端走 REST。

#### F-019 文档生产状态不自动刷新

正式上传返回 `UPLOADED` 后由 Worker 异步处理，但小程序页面只把返回对象插入列表，不轮询状态。

#### F-020 文档“重建索引”重试接口未真正重建

DEV retry 主要切状态；正式重建链路不完整。

#### F-021 删除文档可能遗留对象存储文件和向量

Storage 没有 delete；删除接口只删 DB Document；需确认/实现 chunk、Qdrant、S3/MinIO 的一致清理与补偿任务。

#### F-022 文件校验只依赖扩展名，且一次读入内存后才判断 50MB

**修复**：流式大小限制、MIME/魔数校验、压缩炸弹/解析超时防护、内容安全扫描。

#### F-023 `/ready` 假装“ready”但没有真实探测 Redis/MinIO/Qdrant/LLM

**修复**：生产 readiness 应逐项探测关键依赖；失败返回非 2xx 或明确 unhealthy。

#### F-024 CORS 为 `*`

小程序本身不依赖浏览器 CORS，但仓库还提供 H5/Vue 预览；生产应配置白名单。

#### F-025 JWT 默认 Secret 可在生产误用

**修复**：非 DEV_MODE 下若 Secret 仍是默认/弱值，启动直接失败；增加 Secret 长度与随机性校验。

#### F-026 Profile 中“AI 设置”“数据与隐私”是无点击行为的假入口

**影响**：用户看到可交互项但无法使用；其中“数据与隐私”又恰好是上架合规的重要入口。

#### F-027 “总结资料”快捷入口实际上只是普通聊天入口

没有自动总结动作；文案与行为不一致。

#### F-028 “生成测试”首页入口只跳转学习页

没有直接生成，也没有明确选择知识库。

#### F-029 学习页“确认后才会创建任务”的文案与实际动作不一致

当前点击“生成并开始”后创建计划并立即 activate，没有草案确认阶段。

#### F-030 当前没有可识别的长期记忆实现

仓库描述宣称“长期记忆机制”，现有源码主要是 Conversation/Message 与学习数据，不存在独立可验证的长期记忆抽取、检索、更新、过期/删除机制。

## 3. 微信发布/上架门禁

### R-001 当前 API 地址不能用于正式版

`config.js` 当前是 HTTP + IP + 端口，并且 `devMode=true`。正式发布需要 HTTPS 域名，并在微信公众平台配置 request/uploadFile（若使用 WebSocket则还需 socket）合法域名。

### R-002 `urlCheck=false`

开发时可便于联调，但发布前必须开启合法域名检查进行预验收，避免本地“跳过校验”掩盖真实配置问题。

### R-003 隐私声明为空，但使用了聊天文件选择

代码调用 `wx.chooseMessageFile`；平台隐私保护指引需要与实际处理的用户信息类型匹配。需要在微信公众平台完成隐私保护指引并做真机授权回归。

### R-004 APP/小程序备案

在中国境内提供互联网信息服务，应核验并完成适用的 APP/小程序备案流程；未完成时不得把“代码可上传”视为“可上线”。

### R-005 AI 生成内容标识

AI 文本输出应根据现行生成合成内容标识要求完成显式/必要的隐式标识、用户协议说明与审核材料。

**状态**：本审计分支已在聊天回答上增加“AI 生成 · 请核验重要信息”的显式提示；仍需扩展到 AI 学习计划、AI 测验/解析等生成内容，并完善服务协议与平台材料。

### R-006 生成式 AI 备案/登记适用性需要核验

如果正式功能通过 API 调用已备案模型并面向境内公众提供生成式 AI 能力，应根据实际主体、服务属性和属地要求核验备案/登记义务；上线产品详情需按适用要求公示模型名称及相关备案/登记信息。

### R-007 内容安全未闭环

目前没有看到面向用户输入、上传资料、模型输出的完整违法违规/敏感内容治理链路。正式面向公众前需要按服务范围加入内容安全策略、日志、申诉/处置机制。

### R-008 真实生产环境尚未验收

必须完成：真实 AppID、微信登录、HTTPS 网关、MySQL、Redis/Celery、MinIO/S3、Qdrant、真实 LLM/Embedding、合法域名、真机、弱网、超时、成本/并发测试。

## 5. UI 重构基线（功能不变）

### 视觉方向

采用“高端 AI 学习工作台”风格：

- 背景：极浅冷灰 `#F6F7FB`
- 主文字：`#111318`
- 主品牌：克制靛蓝 `#5B5FF6`
- 成功/掌握：薄荷绿 `#2DBE8C`
- 卡片：纯白 + 极细边框，不堆重阴影
- 大卡圆角 28–32rpx，小卡 20–24rpx
- 统一 8pt/rpx 视觉节奏
- 减少英文 eyebrow 和装饰符号，图标统一使用同一套线性图标
- 不使用大面积廉价渐变，不使用过量玻璃拟态
- 重要 AI 输出必须有明确 AI 标识与来源区域

### 必须分别截图/重做的 6 个页面

1. 首页：学习进度 Hero、四个快捷入口、最近知识库；
2. 知识库：知识库列表、选中详情、文档状态、上传态、创建弹窗；
3. 学习：当前计划、今日任务、新计划弹窗、知识库选择；
4. AI 对话：空态、用户消息、AI 消息、引用、发送/加载态；
5. 测验：答题态、选择态、提交态、结果/解析态；
6. 我的：用户信息、真实统计、设置/隐私入口。

每个页面至少保留：加载、空态、正常数据、错误态；知识库额外保留上传中/失败；聊天保留发送中；测验保留已提交。

### 截图与视觉验收要求

必须使用真实微信开发者工具或真机，固定一套 seed 数据，对每个页面生成“Before/After”截图；不得用 Web 预览截图冒充原生小程序截图。UI 改造只能改变布局、视觉、组件层级和可用性，不得删减核心业务能力。
